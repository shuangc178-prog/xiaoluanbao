# 坚果云备份与恢复：开发说明

本文是小卵包数据持久化的维护门禁。任何新功能只要新增或修改持久化数据，都必须在合并前核对本文，并同步修改备份、恢复与测试。**功能能保存到本机但不能进入完整备份，视为功能尚未开发完成。**

## 1. 当前方案

- 应用通过 HTTPS WebDAV 直接连接用户自己的坚果云账号，不依赖坚果云 App。
- 用户填写坚果云邮箱和“第三方应用密码”；应用密码由 Android Keystore 加密后保存在本机，不写入 `.xlbak`。
- 连接只验证账号并创建当前设备目录，不自动上传或恢复。用户明确完成首次上传或恢复后，才启用自动备份。
- WorkManager 以每天 06:00 为目标安排完整备份。Android 可能因省电、待机或网络条件延后执行；应用每次启动也会检查并补做当天缺失的备份。尚未由用户选择本机或云端数据时，Worker 直接退出。
- 每个逻辑日最多自动上传一次。用户仍可在“本日 -> 数据备份与恢复”中立即备份。
- 恢复前先完整下载并校验 SHA-256，再生成本机安全副本，最后替换各业务模块的数据。
- 云端文件按设备隔离在“我的坚果云/<设备目录>/”中。Xiaomi 14 固定使用 `xiaomi14`；该目录内保存 `xiaoluanbao_yyyy-MM-dd_HHmmss.xlbak`，`xiaoluanbao_latest.properties` 只指向同目录的最新备份。恢复不会读取目录外的数据。
- 连接时使用 WebDAV `MKCOL` 创建当前设备目录，再 GET 该目录的最新索引；有效账号尚无备份时返回 404，表示连接成功。不要用 WebDAV 根目录的 HEAD 验证，坚果云会对有效凭据返回 403。

主要入口：

| 职责 | 文件 |
|---|---|
| 聚合业务快照、恢复与回滚 | `data/backup/AppBackupRepository.kt` |
| `.xlbak` ZIP 读写与安全校验 | `data/backup/BackupArchive.kt` |
| 业务快照二进制编解码 | `data/backup/BackupSnapshotCodec.kt` |
| 坚果云 WebDAV 上传/下载 | `data/backup/NutstoreWebDavClient.kt` |
| 每日调度与断档补做 | `data/backup/CloudBackupWorker.kt` |
| 账号加密存储 | `data/backup/CloudBackupSettingsStore.kt`、`CredentialCipher.kt` |
| 本日页交互 | `ui/backup/CloudBackupController.kt`、`CloudBackupDialog.kt` |

## 2. `.xlbak` 内容

`.xlbak` 是标准 ZIP，当前归档格式版本为 1：

```text
manifest.properties   备份格式、生成时间、逻辑日、应用版本
data.bin              全部结构化业务数据
study/                已导入学习资料的完整文件副本
```

读取时会限制文件大小、条目数、解压总量并拦截路径穿越。恢复只接受受支持的格式版本，云端下载还会与 `xiaoluanbao_latest.properties` 中的大小和 SHA-256 对照。

归档内 `data.bin` 有自己的结构化快照版本，当前为 8。v3 将卡册的“最后抽卡日”从旧版单值改为
`Map<系列 id, 逻辑日>`；v4 为学习资料增加固定分类；v5 增加与卡册同库原子记账的整套兑换休息卡数量；
v6 为每条学习资料增加背单词遮挡状态（`vocabulary_mask`：被遮挡的表格与列、已翻开的行、当时的正文哈希）；
v7 增加阅读器复选框状态（`task_checkbox_state`：被勾选的表格行，含每行文字哈希）；
v8 为每日任务增加实际学习计时（`learningElapsedMillis`、`learningStartedAtEpochMillis`、`hasLearningStarted`）。
读取 v1 / v2 时，旧单值按第一弹 `isekai` 恢复；读取 v1-v3 时，旧资料统一恢复到“看笔记”，
读取 v1-v4 时，新兑换奖励字段按 0 处理，读取 v1-v5 时遮挡状态按“未遮挡”处理，
读取 v1-v6 时复选框状态按“未勾选”处理；读取 v1-v7 时任务学习时长为 0、活动段为空，
保持原任务完成状态，保证已有备份仍可用。

备份生成时将活动计时段结算到备份时刻，并在快照中暂停，不影响本机正在运行的计时。
恢复后所有任务保持暂停，避免把备份离线期间计为学习时间；用户点击后才继续计时。

## 3. 当前数据覆盖清单

| 存储 | 是否进入备份 | 当前覆盖内容 / 排除理由 |
|---|---:|---|
| DataStore `check_in` | 是 | 打卡记录、已看休息卡水位、旧版兑换所得休息卡（升级后继续计入库存） |
| DataStore `daily_plan` | 是 | 所有日期的任务、完成状态、预期开始时间、手动排序、实际学习时间及计时状态、空计划日 |
| DataStore `journal` | 是 | 日记分类、正文、时间戳、自动保存开关 |
| DataStore `card_collection` | 是 | 全部系列的卡片数量、按系列 id 保存的最后抽卡逻辑日映射（所有弹共用每日机会）、新版整套兑换休息卡数量 |
| DataStore `study` | 是 | 学习资料索引、固定分类、版本、阅读位置与进度、背单词遮挡状态、阅读器复选框状态（勾选的表格行与每行文字哈希） |
| `filesDir/study_imports/` | 是 | 已导入 Markdown 资料的实际文件 |
| DataStore `theme` | 是 | 明暗主题选择 |
| DataStore `reminder` | 否 | AlarmManager 请求码、已投递 token 和短期延迟日志均可由恢复后的计划重建；恢复后主动清空并重排 |
| DataStore `cloud_backup` | 否 | 含加密后的坚果云凭据、用户是否已选择数据来源、成功日期和错误状态；属于当前设备的备份基础设施，写入备份会泄露或形成递归依赖 |
| DataStore `agent`（尚未落地，见架构文档 13.1） | 否 | DeepSeek API key 以 Keystore 密文存放，属当前设备凭据：密文换机后无法解开（Keystore 密钥不可导出），进备份只会把用不了的密文搬来搬去；端点与模型名丢失重填一次即可。本行先于实现登记，实现时按同一结论处理，API key 与任何 prompt 上下文都不得进入快照 |
| `filesDir/recovery_safety/` | 否 | 恢复前自动生成的本机安全副本；再次打包会递归膨胀 |
| `cacheDir/cloud_backup_*` | 否 | 上传、下载和解压临时文件，可随时重建 |
| 系统通知、权限、AlarmManager、WorkManager | 否 | Android 系统状态，不能靠业务备份迁移；恢复后按计划和当前设备权限重新建立 |

当前结构化快照由 `AppBackupSnapshot` 定义。完整链路必须同时具备：

```text
Store.snapshot()
    -> AppBackupSnapshot
    -> BackupSnapshotCodec.write/read
    -> Store.replaceAll()
```

任何一段缺失，都不能把该存储标记为“已备份”。

## 4. 新增持久化数据时的强制检查

新增 DataStore、Room 表、SharedPreferences、`filesDir` 文件、用户选取的长期 URI，或给现有模型增加需要保留的字段时，必须依次完成：

1. 在本文“当前数据覆盖清单”中登记存储位置、数据所有者以及是否进入备份。
2. 用户不可重新生成的数据默认必须进入备份。确需排除时，写清楚可重建方式或安全原因。
3. 给对应 Store 增加一次性一致读取的 `snapshot()` 和整包替换的 `replaceAll()`；不要在仓库层直接篡改 DataStore 私有文件。
4. 把数据加入 `AppBackupSnapshot`，并在 `AppBackupRepository.loadSnapshot()`、`applySnapshot()` 和 `validateSnapshot()` 中接通。
5. 更新 `BackupSnapshotCodec`。已有备份必须仍可恢复时，提升格式版本并保留旧版本读取分支，不能只改当前字段顺序。
6. 若包含实际文件，更新 `BackupArchive` 的打包、路径校验、大小限制、解压和回滚流程。
7. 确认恢复失败时能回滚；恢复成功后，所有派生状态是否需要清空并重新生成。
8. 更新往返测试，样例必须给新字段填入非默认值，避免“写漏了但默认值碰巧让测试通过”。
9. 运行备份覆盖守卫、全部单元测试、lint 和打包。

`BackupCoverageInventoryTest` 会扫描源码中的 `preferencesDataStore` 与私有文件存储入口。新增存储而未明确归类时，单元测试会直接失败。测试失败后应先完成上面的开发工作，不能只把新名字加入白名单。

抽卡系列新增字段时还要特别检查三件事：卡数量必须继续使用稳定的全局卡 id，系列 id 必须能随
`lastDrawEpochDays` 完整往返，抽卡与兑换的门禁复核、卡册变更和奖励记账必须在同一个 DataStore
提交中完成。每日机会要检查所有系列当天是否已有记录；映射仍保留系列 id，以记录用户选择的弹并兼容旧备份。

## 5. 必跑验证

```bash
./gradlew.bat :app:testDebugUnitTest
./gradlew.bat :app:lintDebug :app:assembleDebug
```

备份相关测试至少应覆盖：

- 完整快照含中文、换行、非默认值时可无损往返；
- 多弹卡册数量与每弹不同的最后抽卡日可无损往返，旧版单值抽卡日仍能恢复到第一弹；
- 卡册兑换奖励数量与卡册一并往返，v1-v4 旧快照按 0 读取新字段；
- 学习资料分类可无损往返，v1-v3 备份中的旧资料恢复到“看笔记”；
- 背单词遮挡状态可无损往返，v1-v5 备份中的旧资料按“未遮挡”恢复；
- 阅读器复选框状态可无损往返，v1-v6 备份中的旧资料按“未勾选”恢复；
- 任务学习时间和非默认计时状态无损往返，v1-v7 旧备份保留完成状态但学习时间为 0；
- 备份结算活动段后恢复为暂停，离线期间不累计；
- `.xlbak` 可恢复结构化数据和实际资料文件；
- 损坏文件、超限文件、路径穿越、错误哈希和远端文件名注入会被拒绝；
- 每日 06:00 调度与当天只自动备份一次的规则；
- 新增的每一种业务存储已被覆盖守卫识别并明确归类；
- 恢复失败不破坏恢复前数据，恢复成功后提醒等派生状态会重建。

网络端到端验证需要测试用坚果云账号，不能在单元测试中写入真实账号或应用密码。界面与真机恢复流程由人工验证，至少使用一份非空数据执行“备份 -> 修改本地数据 -> 恢复 -> 逐模块核对”。

## 6. 已知边界

- WorkManager 不是精确闹钟，06:00 是目标执行时间，不承诺系统休眠时分秒不差。
- 当前只维护“最新备份”索引，不提供云端历史列表与自动清理；旧 `.xlbak` 会继续保留在坚果云。
- 当前备份未做内容加密。WebDAV 传输使用 HTTPS，但 `.xlbak` 在坚果云中是可读取的 ZIP；若将来保存高敏感数据，需要增加独立的备份加密版本。
- 当前恢复入口只恢复最新备份；恢复前安全副本保留在本机 `filesDir/recovery_safety/`，最多 3 份。
- Android 系统备份/设备迁移不受本方案的覆盖清单约束。Manifest 当前为 `allowBackup="true"`，
  且没有 `dataExtractionRules` / `fullBackupContent`，因此系统可能另外备份 DataStore（包括日记正文）。
  公开分发前必须明确选择关闭系统备份，或配置并验证白名单/排除规则；不能因为 `.xlbak` 已排除凭据，
  就推断 Android 系统备份也遵守同一边界。
